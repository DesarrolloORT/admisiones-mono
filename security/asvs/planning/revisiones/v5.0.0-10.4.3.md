## Aplicabilidad y alcance

El requisito sólo aplica si el sistema opera un authorization server OAuth que retorna authorization codes. En HEAD la API expone autenticación propia por LDAP, segundo factor, cookies HttpOnly, refresh token opaco y JWT; no se localizó endpoint OAuth de autorización o token, registro de clientes, `response_type=code`, `client_id`, `redirect_uri` ni `grant_type=authorization_code`.

Los códigos 2FA y los enlaces de activación/recupero/backoffice son flujos propietarios, no respuestas de autorización OAuth. El JWT de servicio hacia Inscripciones y Pagos expira a los cinco minutos, pero es un token emitido directamente, no un authorization code; su TTL no demuestra el control. La API como cliente de Entra ID (Key Vault) tampoco emite códigos.

No se evaluaron Inscripciones y Pagos, el backoffice, gateway, LDAP ni IdP externos.
