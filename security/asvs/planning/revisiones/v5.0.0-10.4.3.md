## Aplicabilidad y alcance

El requisito sólo aplica si el sistema opera un authorization server OAuth que retorna authorization codes. En el alcance inspeccionado, la API expone autenticación propia por LDAP, segundo factor, cookies HttpOnly, refresh token y JWT; el frontend invoca esas rutas con cookies. No se localizó un endpoint OAuth de autorización o token, registro de clientes, `response_type=code`, `client_id`, `redirect_uri` ni `grant_type=authorization_code`.

Los códigos de 2FA y los enlaces de activación/recuperación de contraseña pertenecen a flujos propietarios: no se retornan como respuesta de autorización OAuth ni se canjean en un token endpoint. El JWT de servicio hacia Inscripciones y Pagos expira a los cinco minutos, pero se emite directamente para la llamada saliente y no es un authorization code; su TTL no demuestra el control requerido.

No se evaluaron la API externa de Inscripciones y Pagos, gateway, LDAP, un proveedor de identidad ni rutas de infraestructura fuera del monorepo. Si alguno opera un authorization server para Admisiones, este resultado no lo cubre.

## Resultado por componente y conclusión

- **API:** NOT_APPLICABLE. Actúa como autenticador y emisor/validador de JWT propios; no se evidenció que opere un authorization server OAuth que emita authorization codes.
- **Frontend:** NOT_APPLICABLE. Consume rutas propias y no procesa una respuesta OAuth de tipo code ni canjea códigos.
- **Core:** NOT_APPLICABLE dentro del alcance del inventario; no se localizó componente OAuth/OIDC en la versión fijada.
- **Integración externa:** fuera del alcance de evidencia disponible. El JWT saliente de cinco minutos no puede usarse como evidencia de esta verificación y no se transfiere el resultado a Inscripciones y Pagos ni a un IdP externo.

La conclusión DOCUMENTADO / NOT_APPLICABLE se limita al monorepo: no existe un authorization code local cuya vida útil pueda medirse contra el máximo de diez minutos. No se ejecutaron tests, builds, runtime, escaneos ni cambios de código o configuración.

## Hallazgos y propuesta documental

No se identificó un hallazgo aplicable en los componentes inspeccionados. La documentación que califica el JWT de servicio como OAuth 2.0 Client Credentials “simplificado” puede inducir a aplicar controles de authorization server a una integración que no implementa authorization code. Responsable candidato: `api-admisiones`. Propuesta documental futura: describirlo como autenticación JWT de servicio propietaria, o documentar el perfil OAuth completo si la API externa realmente lo provee; validar contra contrato y despliegue de esa API. No se aplicó ningún cambio.
