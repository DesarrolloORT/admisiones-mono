## Aplicabilidad y alcance

Incluidos: texto y atributos HTML en frontend, formulario DOM de pagos, correos HTML de activación/recuperación/2FA, transporte SOAP/XML de esos cuerpos y salidas HTTP de API. Un correo HTML también es documento interpretado y su transporte XML constituye otro contexto: codificar uno no prueba el otro.

Búsqueda acotada en frontend src (*.ts/*.html): innerHTML, outerHTML, bypassSecurityTrust, insertAdjacentHTML, bindings de style, style.setProperty, acceso .style. y comentarios con interpolación. No hubo coincidencias en esa búsqueda excluyendo specs. Sí existen atributos dinámicos y svgContent delegado a librería. Esto limita el inventario; no demuestra ausencia global de contextos CSS/comentarios/SVG ni cubre librerías, bundles servidos o scripts de infraestructura.

API: búsquedas de ContentResult/Content, tipos HTML/XML, XmlWriter/XDocument, File, Redirect, headers, cookies y escrituras de cuerpo en entrypoint/AppLogic. No se localizó constructor manual de documentos XML en esos proyectos; SOAP generado en Core sí corresponde al alcance. File de foto devuelve image/jpeg fijo. Se encontró mapeo .html en becas, pero no caller de descarga ni FileDownload/Content-Disposition en el proyecto web buscado. No se declara ese mapeo endpoint HTML expuesto ni NOT_APPLICABLE global.

Límites: intérprete Angular y componentes ORT, middleware completo y hosting efectivo, bytes/MIME de correo entregado, serializador SOAP ejecutado, otros consumidores Core y servicios remotos. URLs/protocolos y JSON/JavaScript quedan como dependencias de 1.2.2/1.2.3; no se abrió otra revisión.

## Hallazgos y propuesta documental

1. **Contrato HTML compartido pendiente (E4–E6).** Helpers aceptan strings como fragmentos sin distinguir texto de markup. Un caller que pase texto arbitrario sin escape podría alterar el documento. Responsable candidato: Core con consumidores. Propuesta para fase posterior: explicitar qué parámetros esperan fragmentos y cuáles texto; tras inventario, codificar las variables de texto en el contexto de uso y mantener markup intencional. Validar con parser HTML y corpus sintético, evitando escape global del body. Hipótesis de riesgo para otros callers, no vulnerabilidad confirmada en los flujos leídos.
2. **Delegación SVG sin cobertura (E2).** getBankSvg/OrtIcon están fuera del código leído. Responsable candidato: frontend y librería ORT. Obtener implementación/versionado y probar si las etiquetas seleccionan SVG fijo o influyen en markup. Solo si hay concatenación arbitraria, definir remediación específica con validación/sanitización acorde al contexto. Sin severidad atribuida.

Propuestas conservadas en esta ficha central. No se verificó disponibilidad de worktrees originales fix/owasp ni se distribuyeron copias; distribución pendiente antes de una fase de remediación, con git branch/worktree list y ref destino explícita. No se cambiaron checkouts ni recrearon repos. No se aplicaron fixes.
