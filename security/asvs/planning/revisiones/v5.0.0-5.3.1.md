## Aplicabilidad y alcance

Registro (reconocimiento), foto, identidad y adjuntos de la declaración jurada aceptan bytes no confiables por `multipart/form-data`; además la API **genera** archivos derivados de entrada no confiable: el recorte de cara, el PDF de la declaración jurada (`AffidavitPdf`) y el ZIP del material de estudio (a partir de URLs de configuración). Los destinos observados son BLOB de Oracle, Redis cifrado con TTL, caché en memoria y, de forma transitoria, el directorio temporal del framework durante el binding multipart. El frontend Angular empaqueta assets públicos versionados; la API sirve `Docs/contracts` en `/contracts` sólo fuera de Production/Preproduction. No se identificó un flujo desde uploads hacia esas carpetas. Todas las descargas pasan por acciones autenticadas que leen BLOB. No se inspeccionaron configuración efectiva de proxy/hosting, permisos reales del despliegue, artefacto publicado ni integraciones externas de almacenamiento (incluido el sistema legacy que comparte la base). Por ello no se declara una exclusión global NOT_APPLICABLE.

## Resultado por componente y conclusión

Frontend: los assets públicos del build provienen de rutas versionadas, sin upload hacia ellas (no re-verificado). API: todos los archivos subidos o generados revisados se guardan en BLOB, Redis cifrado o memoria; su único directorio servido directamente contiene contratos versionados y sólo fuera de producción; el contenedor corre Kestrel sin handlers de ejecución y con el output no escribible. Core: no participa. No se halló un camino desde archivo no confiable hacia carpeta pública ni una ruta que lo ejecute. El hosting real (proxy, montaje de volúmenes, otro tipo de despliegue) podría añadir mapeos o escrituras no versionados. Resultado NEEDS_REVIEW conforme a ADR-002, sin afirmar PASS, FAIL o NOT_APPLICABLE global.

## Hallazgos y propuesta documental

No hay defecto de ejecución confirmado. Riesgo condicionado (sin cambios): si el despliegue permite que una aplicación o integración escriba archivos no confiables en `/contracts` o en assets del frontend, deberá comprobarse el handler de acceso HTTP directo. La lectura del `Dockerfile` (E10) reduce ese riesgo para la imagen de contenedor. Responsable candidato: operaciones/API. Propuesta para futura fase de fixes, sólo si ese montaje existe: separar uploads de directorios públicos y deshabilitar ejecución de código del servidor para esos archivos. No se distribuyó propuesta a otro repo: no hay fix concreto confirmado.
