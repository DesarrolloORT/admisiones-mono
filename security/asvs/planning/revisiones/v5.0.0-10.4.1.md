## Aplicabilidad y alcance

El requisito es condicional: sólo aplica a un authorization server OAuth. La API expone autenticación propia por LDAP (ahora vía paquetes `ORT.Ldap.*`), 2FA, cookies HttpOnly, refresh token opaco y JWT; el frontend consume esas rutas con cookies. En HEAD no se encontró endpoint de autorización, token endpoint OAuth, registro de clientes, `redirect_uri`, `response_type`, `client_id` ni dependencias de servidor OAuth/OIDC en API o Core.

Desde la revisión anterior la API agrega `Azure.Identity` para leer Key Vault con `DefaultAzureCredential`: ahí la API es **cliente** de Microsoft Entra ID (client credentials), no authorization server, y no recibe redirecciones de navegador. El JWT de servicio hacia Inscripciones y Pagos sigue documentado como “OAuth 2.0 Client Credentials Flow (simplificado)”, pero sólo se genera para una audiencia dada.

No se evaluaron Inscripciones y Pagos, el backoffice que firma enlaces de activación (ADR-030), Entra ID ni infraestructura fuera del monorepo.
