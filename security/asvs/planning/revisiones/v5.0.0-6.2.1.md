## Aplicabilidad y alcance

Aplica a contraseña inicial de persona nueva o existente, recuperación por link y cambio de contraseña de persona autenticada. El frontend orienta y valida antes del envío; API y Core imponen la regla antes de invocar LDAP, que conserva la contraseña. No se inspeccionó la política del servidor LDAP ni otros consumidores de Core fuera de esta API. El login verifica una contraseña existente y no es un camino para fijarla.

## Resultado por componente y conclusión

Core fija una longitud mínima de 12 unidades de string de .NET; los tres caminos identificados de API la invocan antes de LDAP. Esto sustenta que el código propio rechaza contraseñas ASCII de menos de 8 caracteres. El frontend presenta el mismo mínimo, pero su validador proviene de un paquete no inspeccionado. No se verificó el proveedor LDAP ni la ejecución HTTP completa, así que el resultado compartido es NEEDS_REVIEW. El mínimo recomendado de 15 no se alcanza; la frase oficial lo recomienda, mientras que el piso obligatorio es 8.

## Hallazgos y propuesta documental

No se confirmó una falta al mínimo obligatorio de este punto. Observación: la política actual de 12 caracteres queda tres por debajo del mínimo fuertemente recomendado de 15. Responsable candidato: API/Core e identidad. Propuesta para fase futura: decidir la política con el dueño LDAP y, si se eleva, coordinar Core, UI y pruebas de borde. Las restricciones de composición y máximo 20 requieren evaluación propia en v5.0.0-6.2.5; no se juzgan como fallo de 6.2.1. Propuesta conservada aquí; distribución a worktrees fix/owasp pendiente, sin verificar sus rutas ni modificar otros repos.
