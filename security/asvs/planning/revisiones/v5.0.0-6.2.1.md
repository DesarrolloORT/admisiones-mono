## Aplicabilidad y alcance

Aplica a contraseña inicial de persona nueva, de persona existente (activación/recuperación), de solicitud aprobada por el backoffice (camino nuevo desde la ref anterior) y al cambio de contraseña de persona autenticada. El frontend orienta y valida antes del envío; la API impone la regla antes de invocar `ILdapService` (paquete `ORT.Ldap.Soap`), que delega en el servicio SOAP que conserva la contraseña. No se inspeccionó la política del servidor LDAP ni otros consumidores. El login verifica una contraseña existente y no es un camino para fijarla. `GeneratePasswordAsync`/`SendPasswordByEmailAsync` del paquete no tienen callers en la API.

## Resultado por componente y conclusión

La API fija una longitud mínima de 12 unidades de string de .NET en `PasswordRules`, y los cuatro caminos identificados (persona nueva, persona existente, solicitud de backoffice y cambio) la invocan antes de LDAP. Esto sustenta que el código propio rechaza contraseñas ASCII de menos de 8 caracteres. El frontend presenta el mismo mínimo, sin re-verificar en esta actualización. No se verificó el proveedor LDAP ni la ejecución HTTP completa, así que el resultado compartido es NEEDS_REVIEW. El mínimo recomendado de 15 no se alcanza; el piso obligatorio es 8.

## Hallazgos y propuesta documental

No se confirmó una falta al mínimo obligatorio de este punto. Observación (vigente en 912fc665): la política de 12 caracteres queda tres por debajo del mínimo fuertemente recomendado de 15. Responsable candidato: API e identidad (la regla ahora vive en `AppLogic.Contracts.Security.PasswordRules`, no en Core). Propuesta para fase futura: decidir la política con el dueño LDAP y, si se eleva, coordinar API, UI y pruebas de borde. Las restricciones de composición y máximo 20 se evalúan en [6.2.5](./v5.0.0-6.2.5.md). Propuesta conservada aquí; distribución a worktrees fix/owasp pendiente.
