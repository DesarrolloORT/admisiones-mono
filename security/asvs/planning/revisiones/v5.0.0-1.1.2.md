## Aplicabilidad y alcance

Requisito compartido aplicable a salidas hacia DOM/HTML, URL y cuerpos HTTP, JSON, headers de descarga y correo. Cambio relevante: en 912fc665 la API ya no arma HTML de correo. Activación, recuperación y 2FA publican contratos tipados de ORT.Messaging.Contracts a Service Bus (7e749347, 73a8855f), y un worker externo los renderiza con las plantillas Razor de TemplatesORT. La codificación final del HTML del correo queda delegada a ese intérprete, que no se inspeccionó (repositorio ajeno).

Core: la API ya no compila Core/MailORT ni Core/LdapService (reemplazados por ORT.Messaging.* y ORT.Ldap.*); solo queda Core/DbConnectionContext. Las filas de correo SOAP y LDAP HTTP de Core se conservan como rastro, fuera del flujo vigente.

Boundaries vigentes: API → frontend → navegador/pagos; API → Service Bus → worker de correo; API → servicios internos (Inscripciones y Pagos, reCAPTCHA); API → Oracle mediante DbConnectionContext; descargas de archivo (Content-Disposition). No se inspeccionaron exhaustivamente templates del frontend, librerías UI, paquetes ORT.*, worker de correo, repositorios Devart, SQL traducido por EF ni visores de logs. No se declara NOT_APPLICABLE por ausencia de coincidencias.

## Resultado por componente y conclusión

- Frontend: NEEDS_REVIEW (sin re-verificar). Se conserva la conclusión original.
- API: NEEDS_REVIEW. Las respuestas JSON y los errores siguen delegados al serializador, y el correo pasó a datos tipados con codificación diferida al intérprete Razor del worker. Esa arquitectura se alinea con el requisito, pero su ejecución no se verificó.
- Core: NEEDS_REVIEW acotado a DbConnectionContext. Los helpers HTML/SOAP y LDAP quedaron fuera del flujo de la API.

DOCUMENTADO / NEEDS_REVIEW conforme a [ADR-002](../../../adr/ADR-002-asvs-evidence-model.md). No se confirmó vulnerabilidad, FAIL, PASS ni severidad.

## Hallazgos y propuesta documental

1. **Contrato de pagos sin evidencia de receptor (E3–E4).** Vigente, sin cambios. Responsables candidatos: frontend/API y dueño de pagos. Obtener el contrato y muestras sintéticas de extremo a extremo antes de proponer remediación.
2. **Contrato implícito de helpers HTML de Core (revisión anterior).** Resuelto para la API en 912fc665: la API ya no usa Core/MailORT ni arma HTML de correo (E7, E10). Si otro consumidor de Core sigue usando EnvioMail, el hallazgo sigue vigente para ese consumidor; queda para el responsable de Core.
3. **Nuevo — codificación del correo delegada a un worker externo (E7).** El cumplimiento depende de que las plantillas TemplatesORT usen la codificación por defecto de Razor (sin Html.Raw sobre FirstName/URL) y de que el link se use en un href con esquema controlado. Responsable candidato: dueño del worker/TemplatesORT. Aportar ref de las plantillas y un correo renderizado con datos sintéticos.

No se aplicaron cambios a código, tests, configuración ni dependencias. No se distribuyeron copias a otros repos.
