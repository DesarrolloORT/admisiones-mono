## Aplicabilidad y alcance

Aplica al cambio voluntario de contraseña de una persona ya autenticada. El menú de perfil lleva a la pantalla de cambio, que envía contraseña actual y nueva a la API. La API toma la identidad del token, solicita el cambio mediante `ILdapService.ChangePasswordAsync` (paquete `ORT.Ldap.Soap`) y, si tiene éxito, renueva la sesión. El restablecimiento por recuperación y la creación inicial son caminos distintos. No se verificaron despliegue, configuración efectiva de LDAP, ejecución HTTP real ni el frontend vigente.

## Resultado por componente y conclusión

Frontend (sin re-verificar) expone el cambio desde el perfil y arma la solicitud. API ofrece un endpoint autenticado, lo conecta con el caso de uso, distingue rechazo de indisponibilidad y renueva la sesión tras el cambio. El paquete `ORT.Ldap.Soap` llama una operación específica de cambio en el proveedor externo y examina su resultado. Esto demuestra que el flujo existe en el código. No hay evidencia reproducible de que un usuario pueda completarlo en el ambiente desplegado; resultado compartido NEEDS_REVIEW. No se atribuye una vulnerabilidad.

## Hallazgos y propuesta documental

No se confirmó un defecto propio de este punto. Para cerrar la validación, API/identidad debería probar con una cuenta de ensayo que el endpoint responde éxito sólo cuando el servicio LDAP cambia efectivamente la contraseña, que luego se puede autenticar con la nueva y que el refresh token anterior queda inválido. La prueba debería cubrir también el camino de error sin registrar contraseñas. No hay fix concreto ni propuesta distribuida.

## Pendientes y dependencias

- API/identidad: aportar configuración y disponibilidad del servicio SOAP/LDAP del ambiente objetivo; ejecutar una prueba controlada de cambio, autenticación posterior y uso del refresh anterior, con credenciales de ensayo.
- Frontend: comprobar en el despliegue y sobre el checkout vigente que una persona autenticada puede abrir el menú, enviar el formulario y ver el resultado.
- Ejecutar, en una fase autorizada, los tests existentes citados.
- La exigencia de contraseña actual se evalúa en [6.2.3](./v5.0.0-6.2.3.md); las reglas de contraseña nueva en los puntos posteriores de V6.2.
