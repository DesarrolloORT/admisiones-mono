## Aplicabilidad y alcance

Aplica al cambio voluntario de contraseña de una persona ya autenticada. El menú de perfil lleva a la pantalla de cambio, que envía contraseña actual y nueva a la API. La API toma la identidad del token y solicita el cambio al servicio SOAP de LDAP por medio de Core. El restablecimiento de contraseña por recuperación y la creación inicial son caminos distintos; no se usan para demostrar este requisito. No se verificaron despliegue, disponibilidad del menú, configuración efectiva de LDAP, ejecución HTTP real ni otros clientes de Core.

## Resultado por componente y conclusión

Frontend expone el cambio desde el perfil y arma la solicitud. API ofrece un endpoint autenticado, lo conecta con el caso de uso y distingue éxito de falla. Core llama una operación específica de cambio en el proveedor externo y examina su resultado. Esto demuestra que el flujo existe en el código. No hay evidencia reproducible de que un usuario pueda completarlo en el ambiente desplegado, por lo que el resultado compartido es NEEDS_REVIEW. No se atribuye una vulnerabilidad confirmada.

## Hallazgos y propuesta documental

No se confirmó un defecto propio de este punto. Para cerrar la validación, el responsable candidato de API/identidad debería probar con una cuenta de ensayo que el endpoint responde éxito sólo cuando el servicio LDAP cambia efectivamente la contraseña, y que luego se puede autenticar con la nueva. La prueba debería verificar también el camino de error sin registrar contraseñas. No hay fix concreto ni propuesta distribuida a worktrees fix/owasp en esta iteración.

## Pendientes y dependencias

- API/identidad: aportar configuración y disponibilidad del servicio SOAP/LDAP del ambiente objetivo; ejecutar una prueba controlada de cambio y autenticación posterior, con credenciales de ensayo y sin conservar secretos.
- Frontend: comprobar en el despliegue que una persona autenticada puede abrir el menú, enviar el formulario y ver el resultado; confirmar permisos de la ruta.
- Ejecutar, en una fase autorizada, los tests existentes citados. Su ejecución aislada seguiría sin demostrar el cambio efectivo en LDAP.
- La exigencia de contraseña actual se evalúa específicamente en v5.0.0-6.2.3; las reglas de contraseña nueva en los puntos posteriores de V6.2. No se abrieron esas revisiones.
