## Identificación

- **ID y nivel mínimo:** v5.0.0-6.2.6, L1.

## Aplicabilidad y alcance

El control aplica al navegador en login (contraseña actual), establecimiento/activación de contraseña (nueva y confirmación) y cambio voluntario (actual, nueva y confirmación): seis campos en tres vistas. El límite relevante es la plantilla Angular y el `input` HTML entregado al navegador. API y Core reciben las contraseñas pero no determinan el atributo visual `type`; en 912fc665 la API no sirve HTML propio con campos de contraseña (sólo endpoints JSON/multipart y Swagger fuera de producción). No se verificaron bibliotecas externas, pantallas fuera del árbol ni la aplicación desplegada.

## Resultado por componente y conclusión

**Frontend: NEEDS_REVIEW.** El código propio leído en `86979de2` respalda que los seis campos inician enmascarados y permiten verlos sólo mediante su botón. Según ADR-002, la lectura de código y de pruebas no ejecutadas no basta para PASS; falta comprobar el DOM en un navegador real y re-verificar sobre el checkout vigente.

**API y Core:** el atributo de un campo HTML no les aplica directamente. **Conclusión global: NEEDS_REVIEW.**

## Hallazgos y propuesta documental
