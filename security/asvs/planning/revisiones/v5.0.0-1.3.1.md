## Aplicabilidad y alcance

Frontend (evidencia original): no se encontró WYSIWYG, contenteditable ni editores enriquecidos conocidos, ni sinks innerHTML/bypassSecurityTrustHtml/DOMPurify y similares en src/ y lockfile. Hay textareas de texto libre en becas y consulta de resultado; el reglamento es HTML fijo. Esto acota, no demuestra ausencia global.

API: acepta JSON y, desde ADR-019 (90ccee3d), multipart/form-data con IFormFile para fotos, documentos de identidad y adjuntos de becas. Aplica un filtro global de sanitización HTML a los argumentos MVC. Se incluyen filtro, registro, tests existentes, el flujo de listas de texto libre de la encuesta inicial y la descarga de archivos de becas.

Correo: desde a092f905 la API publica mensajes tipados en Service Bus (ORT.Messaging) y un worker externo los renderiza con templates Razor de TemplatesORT. Core/MailORT y su CuerpoParrafos ya no se consumen. El render HTML del correo queda fuera de este repositorio.

Core consumido: solo DbConnectionContext, sin manejo de HTML. Fuera de inspección: librerías privadas del frontend, worker de correo y TemplatesORT, servicios de pagos, otras aplicaciones que leen la misma DB y otros consumidores de Core. No se afirma NOT_APPLICABLE global.

## Hallazgos y propuesta documental

### H1 — Cobertura de colecciones del filtro no demostrada (vigente)

Condición: SanitizeObject refleja propiedades y no enumera ni reemplaza strings dentro de colecciones. SaveInitialSurveyRequest sigue incluyendo listas de texto que solo se normalizan. Si un consumidor las trata como HTML, el filtro global no las cubre. Evidencia E5/E9/E10. No se confirma vulnerabilidad ni severidad.

Propuesta futura: acordar qué campos son texto y cuáles admiten HTML; mantener texto como texto con codificación en el receptor; si hace falta sanitizar HTML en colecciones, extender mínimamente el filtro existente. Validar listas, arrays y diccionarios efectivamente usados.

### H2 — Tests de registro no acreditan el filtro global (vigente)

Condición: E8 sigue verificando solo una colección DI no vacía o un conteo de descriptores. Propuesta futura: comprobar MvcOptions.Filters y un request real que atraviese binding/filtro/action con inputs sintéticos.

### O1 — Descarga de adjuntos legacy con Content-Type text/html (observación nueva)

Condición: E12. Si existieran en la DB adjuntos de becas legacy con extensión .html subidos por usuarios, la API los devolvería como text/html, aunque como descarga y con nosniff. Impacto potencial bajo y no demostrado; corresponde más a V5 (manejo de archivos) que a este requisito. Propuesta futura: confirmar con DBA si hay registros con esa extensión y, si no corresponde, mapear .html a application/octet-stream. No se distribuyó propuesta.
