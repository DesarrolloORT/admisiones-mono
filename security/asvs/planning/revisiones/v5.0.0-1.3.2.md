## Resultado por componente y conclusión

- **Frontend — NEEDS_REVIEW:** evidencia original sin re-verificar; falta bundle real, dependencias privadas y script externo.
- **API — NEEDS_REVIEW:** sin motor de expresiones propio. Aparece un uso de ejecución dinámica controlado (EVAL Lua con script constante y datos separados) y validación de esquemas definidos en código. Faltan dependencias transitivas, paquetes ORT.* y artefacto efectivo.
- **Core consumido — NEEDS_REVIEW:** reducido a DbConnectionContext, sin evaluadores.

**Conclusión compartida: DOCUMENTADO / NEEDS_REVIEW**, según [ADR-002](../../../adr/ADR-002-asvs-evidence-model.md). No hay un flujo confirmado de entrada no confiable hacia ejecución dinámica que justifique FAIL, ni evidencia suficiente para PASS o NOT_APPLICABLE.

## Hallazgos y propuesta documental

No se confirma una vulnerabilidad ni se propone un fix concreto. Se registra una observación nueva:

- **O1 — EVAL Lua en el rate limiter (E8).** Uso de una función de ejecución dinámica en Redis. Cumple la forma que pide el requisito cuando no hay alternativa (script fijo, entrada solo como argumentos), y la decisión PLA-01 lo justifica por atomicidad. No es un hallazgo; se deja para que una futura modificación no concatene datos en el script. Validación futura: test de integración con claves y argumentos sintéticos que contengan comillas, saltos de línea y fragmentos Lua, comprobando que no alteran el comportamiento.

El gap de cobertura sigue siendo la falta de inventario y evidencia del código efectivamente ejecutado en dependencias, paquetes privados y hosting. Responsables candidatos: frontend y plataforma para bundle/scripts; API y mantenedores de ORT.* para assemblies y configuración efectiva; equipo de mensajería para el render Razor del worker.

No se distribuyeron copias en worktrees fix/owasp: no hay remediación concreta.
