## Resultado por componente y conclusión

- API: **NEEDS_REVIEW**. Hay uso observable de EF/LINQ y comandos Redis con argumentos separados; faltan comandos/bindings reales y esquema desplegado. NextId(string) tiene un boundary débil, sin caller productivo identificado en la API revisada.
- Core: **NEEDS_REVIEW**. La variante enum restringe identificadores; las variantes string no lo hacen localmente. Los callers ModBandeja encontrados suministran constantes. No hay evidencia suficiente de una entrada atacante hasta ese SQL ni cobertura de otros consumidores.
- Frontend: **NEEDS_REVIEW** dentro del control compartido; inventario acotado sin sink DB local identificado. El control de la persistencia corresponde a servidor/Core y servicios externos.
- Conclusión global: **NEEDS_REVIEW**, conforme a [ADR-002](../../../adr/ADR-002-asvs-evidence-model.md). DOCUMENTADO indica cierre del análisis documental de este punto; no acredita PASS/FAIL, vulnerabilidad confirmada ni riesgo aceptado. No se incorporaron resultados históricos como prueba actual.

## Hallazgos y propuesta documental

### H1 — Identificador de secuencia string sin validación en repositorios genéricos

Condición: E5/E7 interpolan un string en SELECT ... NEXTVAL FROM DUAL. Impacto potencial: alterar la estructura SQL si algún consumidor permite un identificador no confiable; hoy los callers Core encontrados usan constantes y no se confirmó esa ruta atacante. Sin severidad definitiva ni explotación demostrada.

Responsables candidatos: mantenedor del template Devart/API y mantenedores ModBandeja/ModGenericBase Core. Propuesta para fase posterior: restringir a secuencias permitidas mediante enum o allowlist exacta en el template/origen de generación, o eliminar la API string si el inventario completo confirma que es innecesaria. Los identificadores SQL no se resuelven simplemente agregando un parámetro de valor. Conservar transacciones y compatibilidad; no editar a mano código generado.

Validación futura: pruebas de rechazo de identificadores fuera del conjunto antes de ejecutar comandos, constantes válidas y traducción Oracle; verificar regeneración y consumidores contra la ref Core que vaya a consumirse.
