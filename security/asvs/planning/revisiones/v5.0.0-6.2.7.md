## Aplicabilidad y alcance

El control aplica al navegador en login (contraseña actual), establecimiento de contraseña tras activación o recuperación (nueva y confirmación) y cambio voluntario (actual, nueva y confirmación): seis campos en tres plantillas. El límite es la plantilla Angular, la directiva `ortInput` de `@desarrolloort/components`, el DOM servido y las integraciones del navegador o del gestor. API y Core reciben valores, pero no deciden si el usuario puede pegar o usar autocompletado. Observación de API: el filtro global `SanitizeAttribute` puede alterar el valor recibido (ver [6.2.8](./v5.0.0-6.2.8.md)); afecta la exactitud, no la posibilidad de pegar o autocompletar.

## Resultado por componente y conclusión

**Frontend: NEEDS_REVIEW.** Las plantillas brindan pistas estándar de autocompletado y el código propio leído no bloquea pegado. Falta probar la interacción efectiva en la aplicación servida y re-verificar sobre el checkout vigente. **API/Core:** sin control directo sobre esta capacidad de UI. **Conclusión global: NEEDS_REVIEW**, según ADR-002.

## Hallazgos y propuesta documental
