## Aplicabilidad y alcance

Aplica al cambio voluntario de contraseña de una persona autenticada: formulario Angular → POST /person/change-password → caso de uso People → `ILdapService` (paquete `ORT.Ldap.Soap`) → servicio SOAP LDAP. El sujeto se toma del token, no del body. La recuperación y el alta usan `ForceChangePasswordAsync` sin contraseña actual; son flujos distintos. No se inspeccionó el código del proveedor SOAP/LDAP, ni el despliegue o las peticiones HTTP reales.

## Resultado por componente y conclusión

Frontend (sin re-verificar) presenta y envía ambos valores. API exige ambos campos en el contrato y su lógica rechaza una contraseña actual vacía antes de llamar al paquete LDAP, que incluye ambas en la petición SOAP y propaga un resultado negativo. La parte decisiva —que el proveedor rechace una contraseña actual incorrecta y no cambie la contraseña en ese caso— no se puede comprobar leyendo el cliente. Resultado compartido: NEEDS_REVIEW; no se atribuye vulnerabilidad ni PASS global.

## Hallazgos y propuesta documental

No se confirmó un defecto de implementación propio de este punto. La dependencia de seguridad sigue siendo el comportamiento del proveedor SOAP/LDAP: si éste aceptara un valor anterior incorrecto, una sesión autenticada podría cambiar la contraseña sin demostrar conocimiento de la actual. Responsable candidato: identidad/API. Propuesta para fase posterior: verificar contrato e implementación del proveedor y ejecutar pruebas negativas controladas. No hay fix concreto ni propuesta distribuida.

## Pendientes y dependencias

- Identidad/API: aportar contrato o implementación del servicio SOAP `CambiarPassword` y comprobar que valida `viejoPassword` para el usuario indicado.
- Identidad/API: en ambiente de ensayo, invocar el endpoint autenticado con contraseña actual incorrecta y nueva válida; comprobar rechazo y que la anterior sigue funcionando. Repetir con la actual correcta. Esta evidencia decide PASS/FAIL.
- API: verificar por HTTP que omitir, enviar null o dejar vacía cada contraseña produce rechazo sin llamar al proveedor.
- Ejecutar los tests existentes en una fase autorizada.
- Relación: [6.2.2](./v5.0.0-6.2.2.md) cubre disponibilidad del cambio. Recuperación y contraseña inicial usan `ForceChangePasswordAsync` y se analizan en sus requisitos.
